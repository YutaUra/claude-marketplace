# 画面の中身と注釈の作法

## ゾーニング

1. 画面に載せる情報と操作を全部書き出す
2. 利用者のタスクにとっての重要度で順位を付ける
3. 少数（3〜6 個）のゾーンにまとめ、それぞれに役割の名前を付ける
4. ゾーンの配置を決めてから、ゾーンの中の要素を置く

- 1 つのゾーンが 2 つの役割を持っているなら、それは 2 つのゾーンを 1 つに描いている。分ける
- 要素レベルの議論（ボタンの文言など）を、ゾーンを決める段階に持ち込まない

## まとまりは余白で作る

- 関係するもの同士は近づけ、関係しないまとまりの間は空ける。まず余白だけで区切れないか試す
- 枠線・背景色の箱で囲むのは、余白だけでは区切れないときだけ。全部をカードで囲むと、優先度が見えなくなり、まだ決めていない「カード部品」を決めたように見える
- 横幅いっぱいの区切り線は「ここでページが終わる」ように見え、スクロールされにくくなる

## レイアウトパターン

| パターン | 合う場面 | 合わない場面 |
| --- | --- | --- |
| 1 カラム | フォーム・記事・モバイル全般など、一直線に進むタスク | 項目を比べる必要があるとき |
| サイドバー + 本体 | 常設のナビ・フィルタの横で作業する | タブレット幅未満（畳み方を決める） |
| 一覧 + 詳細 | 一覧を見ながら 1 件ずつ見る | 詳細に集中が必要なとき |
| カードグリッド | 同格のものを眺めて選ぶ | 特定の属性で比べたいとき（表にする） |
| ダッシュボード | 状態をざっと把握する | すべてが同じ重要度のとき |
| ウィザード | 1 画面 1 判断で進める | 全体を見渡したいとき（進捗表示と組み合わせる） |

よく見かけるからではなく、利用者のタスクで選ぶ。パターンは出発点であって答えではない。

## 中身の書き方

- 本物のラベルを使う:「ストレージ使用量 14.2 GB / 15 GB」「〇〇さんが 3 分前にコメント」
- 現実の量にする: マーケットの一覧なら 2 件ではなく 6 件以上並べる。フィードならファーストビューの外まで描く
- 端の場合も入れる: 長い名前・長い複合語、0 件、47 件、エラー
- 数字は利用者がその数字を必要とする場所にだけ置く。ラベルの飾り（「注文 · 4」）や全行の件数表示を、埋め草として置かない
- 現実の画面の情報量に揃える。実際のプロダクトのスクリーンショットをグレースケールにしたとき、同じ場所に同じくらいの量があるのが目安

## 状態

データを扱う画面では、次のうち**構造が変わるもの**を別フレームか注釈で示す:

| 状態 | 示すこと |
| --- | --- |
| 空（初回・0 件） | 何が無いのか、最初に何をすればよいか（主要操作への誘導） |
| 読み込み中 | スケルトン（灰色の形）で配置を保つか、操作の中だけでスピナー + 文言（「送信中…」）を出すか |
| エラー | どこに出すか（入力欄の下 / 画面上部 / トースト）、復帰方法 |
| 多すぎる | 長い一覧の打ち切り、ページング、長い文字列の折り返し・省略 |
| 権限なし | 操作を隠すのか、無効化して理由を出すのか |

## 注釈

- 番号付きマーカーを、注釈する要素の余白か隅に置く（文字や操作の上に重ねない）。画面ごとに 1 から振る
- 番号と説明を 1 対 1 で対応させ、説明は短い 1 文にする
- 書く対象:
  - 配置の理由（「問い合わせの 4 割が検索から来るので、ヘッダーに常設」）
  - 条件で変わる表示、業務ロジック
  - 定石から外れた部分と、その理由
  - 空・エラー・権限なしのときの振る舞い
  - 主要操作を押した結果（どこへ行くか、何が起きるか）
  - 未解決の問い（「？」で終わる文にする）
- 書かない対象: 見れば分かること（「ここは検索ボックス」）、画面の目的の言い直し
- 要素に結び付かない問いだけを、最後の「未解決の問い」にまとめる

## breadboard（言葉で書くフロー）

画面のレイアウトがまだ問いでないとき、フローを言葉で書く:

```
[商品一覧]
  - 検索欄
  - 商品カード → [商品詳細]
  - 絞り込み → [絞り込みシート]
[商品詳細]
  - 「カートに入れる」 → [カート]（在庫切れなら → 入荷通知の登録）
  - 戻る → [商品一覧]
```

- `[場所]`（画面・ダイアログ）、その中の操作、矢印の行き先を書く
- すべての操作の行き先を書き切る。行き先の無い操作（行き止まり）や、どこからも来られない場所がここで見つかる

## wireflow（画面遷移）

- 画面をフローの順に左から右へ並べる
- 矢印は**遷移を起こす操作（ボタン・行）から**伸ばし、操作名を動詞で書く（「① 注文する」）。画面全体から画面全体への矢印にしない
- 成功の道だけでなく、各分岐点の**別の道**（入力エラー・0 件・失敗・権限なし・戻る）も描く。別の道は破線にする
- 矢印やラベルは画面の外（背景側）に描く。画面の中に流れの情報を混ぜない

# PC とモバイルの描き分け

ワイヤーフレームを描く前に必ず読む。対象が両方なら「両方を描くとき」まで読む。

## 共通: 実寸で描く

- 縮小したキャンバスに描かない。**実際の画面サイズ（1:1）の枠の中に描く**。縮小すると、縦の余裕のなさ・指の届く範囲・ファーストビューに入る量を見誤る。
- 描いたら、**ファーストビュー（スクロールせずに見える範囲）に何が入るか**を数える。主要操作がファーストビューの外に出ていたら、それは配置の問題として扱う。
- 幅はデバイス名ではなく、**中身が読みにくくなる幅**で区切る（後述のブレークポイント）。

## モバイル

| 項目 | 既定値 |
| --- | --- |
| キャンバス | 375×812（基準）。小さい端末の確認は 360×640、大きい端末は 430×932 |
| 外枠 | 端末の枠 + ステータスバー（上 44px 前後）+ ホームインジケーター（下 34px 前後）を描き、そこには要素を置かない |
| レイアウト | 1 カラム。横に並べるのは小さなチップ・アイコン・2 列のサムネイル程度まで |

### 親指の届く範囲

片手・右手親指で操作する人が多いため、画面は届きやすさで 3 つに分かれる:

- **下側中央（届く）**: 主要操作（作成・送信・購入）、主要ナビゲーション。下部固定のボタン、下タブバーを使う
- **中段の左右（少し伸ばす）**: 一覧の各行、二次操作
- **上の両隅（届きにくい）**: 戻る・閉じる・設定・削除など、頻度の低い操作や誤タップさせたくない操作を**わざと**置く

### ナビゲーション

- 主要な行き先が 3〜5 個なら**下タブバー**に常に見せる。ハンバーガーメニューに隠すのは、行き先が多すぎて画面に出せないときの最後の手段
- 6 個以上あるなら、まず情報設計（行き先のまとめ方）を見直す。それでも多ければ「その他」タブに寄せる
- 画面の階層を下りたら、上部に「戻る + 画面タイトル」のバーを置く

### 操作と入力

- タップできる領域は見た目より大きく取り、隣の操作との間を空ける。サイズは対象プラットフォームの指針（iOS は 44pt、Android は 48dp が目安）で注釈し、最終的な確認は実装時に回す
- ホバーは無い前提で描く。ホバーでしか出ない情報・操作を作らない
- 入力フォームは 1 列。ソフトウェアキーボードが下半分を覆うので、入力中に主要ボタンが隠れないか注釈する
- 補助的な選択・確認は**ボトムシート**、重い確認・中断はダイアログ、と使い分ける
- 横に長い表は作らない。カードの縦積み、または「一覧 → 詳細」の画面分割にする

### ファーストビューの目安

375×812 なら、ヘッダー + 一覧 3〜5 行 + 下タブバー程度しか入らない。それ以上を入れようとしているなら、情報を削るか画面を分ける。

## PC

| 項目 | 既定値 |
| --- | --- |
| キャンバス | 1440×900（基準）。狭いノート PC の確認は 1280×800 |
| 外枠 | ブラウザの枠（タブ・アドレスバー）を簡略化して描く。Web アプリなら URL も仮で書くと、画面の位置付けが伝わる |
| コンテンツ幅 | 本文を含む領域は最大幅（目安 1200px 前後）を決めて中央寄せ。管理画面・ダッシュボードは全幅 |

### 視線の流れ

- 左上から読み始め、文字の多い画面は F 字、要素の少ない画面（LP など）は Z 字に流れる。最重要の情報と主要操作はこの線上に置く
- 本文は **1 行 45〜75 文字**（日本語なら 35〜40 字程度）に収まる幅にする。全幅に伸ばした長い行は読まれない

### ナビゲーション

- 行き先は隠さず常に見せる。少なければ**上部ナビ**、多い・階層がある・作業中に頻繁に切り替えるなら**左サイドバー**
- PC 幅でハンバーガーメニューは使わない
- パンくずは 3 階層以上あるときだけ

### PC で選びやすいレイアウトパターン

| パターン | 合う場面 | 合わない場面 |
| --- | --- | --- |
| サイドバー + 本体 | 常設のナビやフィルタの横で作業する | 狭い幅（畳み方を決めておく） |
| 一覧 + 詳細（master-detail） | 一覧を見ながら 1 件ずつ処理する | 詳細に集中が必要、または一覧自体が作業の中心 |
| 表 | 項目を横に比べる・並べ替える | 画像が主役のもの（カードグリッドにする） |
| ダッシュボード | 状態を一目で把握する | すべてが「重要」で優先度が無いとき |

### 操作

- ホバー・右クリック・キーボードショートカット・ドラッグ＆ドロップが使える。ただし**ホバーでしか見えない操作**は発見されにくいので、主要操作には使わない
- 主要操作は、ページ上部の右か、フォームの末尾（左揃えの入力なら左下）のどちらかに揃える。画面ごとにばらつかせない
- 確認はモーダル、補助的な編集は右から出るドロワー、と使い分ける

## 両方を描くとき

1. **モバイルから描く**。一番狭い枠で、必要な中身と主要な流れだけに絞る。PC の画面を縮めてモバイルを作ると、タップ領域が小さくなり、主要操作が上隅に追いやられ、ファーストビューに入らない量を抱え込む
2. 同じゾーンを、幅に応じて広げる。目安の区切りは次の 3 つ（中身が崩れる幅に合わせて調整する）:

   | 幅 | レイアウト | ナビゲーション |
   | --- | --- | --- |
   | 〜599px（compact） | 1 カラム | 下タブバー |
   | 600〜839px（medium） | 1〜2 カラム。補助パネルが出る | 左のアイコンレール |
   | 840px〜（expanded） | 2〜3 カラム。一覧 + 詳細が並ぶ | ラベル付きサイドバー |

3. **行き先の集合はすべての幅で同じにする**。変わるのは入れ物（タブバー → レール → サイドバー）だけ。幅によって行き先が増えたり消えたりすると、利用者の頭の中の地図が崩れる
4. 幅ごとに**別のフレーム**として並べ、切り替わる理由をデバイス名ではなく中身で注釈する（例:「一覧と詳細が両方収まるので 840px から 2 ペイン」）
5. 両方で並び順が変わる要素（PC では右カラム、モバイルでは本文の下、など）には注釈を付ける。並び順の変化はアクセシビリティ（読み上げ順）にも影響する

# UX ライティング（画面の文言）

画面の文言は飾りではなく操作の一部。ラベルが曖昧なら、ユーザーは押す前に迷い、押した後に驚く。

## ユーザーは読まずに流し読みする

- 常に流し読みする人が 79%、逐語的に読んだのは 16%（Nielsen 1997。数値は古いので傾向として使う）。
- 文章を簡潔にする、流し読みしやすい構成にする、客観的に書く、の 3 つを組み合わせると、ユーザビリティが大きく上がった。
- F 字型の読み方は、書式の無い文章・効率重視・読む動機が弱い、の 3 条件がそろうと起きる。右側や段落の後半に置いた重要情報は読み飛ばされる。
- 書き方:
  - 結論を先に書く（逆ピラミッド）
  - 見出し・ラベル・リンクは、行頭の 2〜3 語で中身が分かるようにする（「〇〇について」で始めない）
  - 1 段落 1 論点、箇条書き、文字量は半分を目指す
  - 注意書きの長文はほぼ読まれない。読まれなくても事故が起きない設計にし、文言は補助にする

出典: https://www.nngroup.com/articles/how-users-read-on-the-web/ / https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/

## ボタンとリンク

- **動詞で始め、対象が曖昧なら名詞を足す**: 「削除」ではなく「フォルダを削除」。「送信」ではなく「申請を送信」。
- **押した結果を書く**: 確認ダイアログでは「OK / キャンセル」ではなく「3 件を削除 / 削除しない」。
- **「次へ」より行き先**: ウィザードでは「支払い方法へ」。
- **同じ操作は全画面で同じ言葉**: 「保存」「登録」「確定」を同じ意味で混ぜない。
- **追加の入力が要る操作には「…」**: 「名前を付けて保存…」。
- **リンクは行き先が分かる言葉に**: 「こちら」「詳しくはこちら」を単独のリンクにしない。
- 2〜4 語程度に収める。「戻る」「キャンセル」「設定」のような定番は動詞でなくても通じる。

出典: https://www.nngroup.com/articles/ui-copy/

## ラベルと用語

- **ユーザーの言葉で書く**: 社内用語・部署名・データベースの項目名・ブランド化した機能名を、そのまま見せない。どうしても使うなら近くで説明する。
- **技術用語を見せない**: エラーコード、「セッション」「キャッシュ」「サービスワーカー」。開発者向けツールのように、利用者がその用語を使う場合は例外。
- **同じものには同じ名前**: 「顧客」「取引先」「クライアント」を混ぜない。用語集を作ると揃う。
- **肯定形で書く**: トグルは「通知を受け取る」。「通知を無効にしない」のような二重否定を作らない。
- **単位・書式を示す**: 「金額（税込・円）」「YYYY/MM/DD」。ただし書式は受け入れて整えるほうが先（`task-efficiency.md`）。

## エラー・空状態・確認の型

| 場面 | 型 | 例 |
| --- | --- | --- |
| 入力エラー | 何が問題か + どう直すか | 「郵便番号は 7 桁の数字で入力してください（例: 1000001）」 |
| システムエラー | 何が起きたか + ユーザーの作業はどうなったか + 次の一手 | 「保存できませんでした。入力内容はこの画面に残っています。通信を確かめて、もう一度保存してください」 |
| 初回の空状態 | ここに何が入るか + 最初の一手 | 「請求書はまだありません。最初の請求書を作ると、ここに一覧で表示されます」[請求書を作成] |
| 絞り込みで 0 件 | 条件 + 外す導線 | 「『未払い』かつ『2026 年 10 月』の請求書はありません」[条件をクリア] |
| 権限なし | 理由 + 誰に何を頼むか | 「この設定を変えるには管理者権限が必要です。管理者（山田さん）に依頼してください」 |
| 取り消せない操作の確認 | 対象 + 結果 + 取り消せないこと | 「『2026 年度予算.xlsx』を完全に削除します。この操作は取り消せません」[完全に削除] [削除しない] |
| 完了 | 何が終わったか + 次にできること | 「申請を送信しました。承認されるとメールでお知らせします」 |

## トーン

- 頻繁に出るエラーでユーモアを使わない（飽きられ、苛立たせる）。ゼロ件ページの冗談は馬鹿にされたと受け取られることがある。
- 謝罪は、システム側の問題のときだけ短く。ユーザーの入力ミスに「申し訳ありません」を重ねると冗長になる。
- 断る選択肢に罪悪感を与える文言（「いいえ、損をしたいです」）は confirmshaming というダークパターン（`accessibility-ethics.md`）。

## 確かめ方

- 文言だけを抜き出して読み、画面を見なくても何が起きるか分かるか。
- ボタンのラベルだけを並べて、どれを押せば目的が達成できるか分かるか。
- 用語が画面をまたいで揃っているか（`rg` で同義語を探す）。

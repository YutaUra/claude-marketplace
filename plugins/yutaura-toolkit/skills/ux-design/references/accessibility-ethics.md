# アクセシビリティ・倫理・信頼

## WCAG 2.2 のうち UX 設計で効く基準

アクセシビリティは「一部の人のための追加機能」ではなく、負担を減らす設計の一部。認知・運動・視覚の負担が大きい人で問題になる箇所は、全員にとっても負担になっていることが多い。

| 基準 | レベル | 設計で決めること |
| --- | --- | --- |
| 1.4.1 色の使用 | A | エラー・必須・状態を色だけで示さない。アイコンか文言を添える |
| 1.4.3 コントラスト | AA | 文字 4.5:1、大きい文字（約 24px 以上、太字なら約 18.5px 以上）3:1。プレースホルダーも対象。四捨五入しない |
| 1.4.11 非テキストのコントラスト | AA | 入力欄の境界、状態の表示、フォーカス表示、意味のあるアイコンは 3:1 |
| 2.2.1 タイミング調整可能 | A | 時間制限はオフ・延長できるようにする。警告後 20 秒以上の猶予と簡単な延長手段 |
| 2.4.11 フォーカスの非隠蔽 | AA | フォーカスした要素が固定ヘッダー・フッター・Cookie バナーで完全に隠れない（`scroll-padding` で対処） |
| 2.5.7 ドラッグ操作 | AA | ドラッグでしかできない操作に、クリック・タップだけでできる代替を用意する（並び替えに「上へ / 下へ」） |
| 2.5.8 ターゲットサイズ（最小） | AA | 24×24 CSS px 以上（`ia-navigation-mobile.md`） |
| 3.2.6 一貫したヘルプ | A | 問い合わせ・FAQ・チャットを複数ページに置くなら、同じ順序の位置に置く |
| 3.3.3 エラー修正の提案 | AA | 直し方が分かるなら示す |
| 3.3.4 エラー防止（法的・金銭・データ） | AA | 取り消し・入力チェック・送信前の確認のどれかを用意する |
| 3.3.7 冗長な入力 | A | 同じ手続きで入力済みの情報を再入力させない |
| 3.3.8 アクセシブルな認証（最低限） | AA | ログインで記憶・転記・計算・パズルを唯一の手段にしない。パスワードの貼り付けとパスワードマネージャを妨げない。確認コードは貼り付けられるように。パスキー・メールリンクは適合 |
| 4.1.3 ステータスメッセージ | AA | フォーカスが移らない状態変化（件数、保存完了、エラー）を支援技術に伝える |

- 自動検査で見つかるのは一部だけ。キーボードだけで主要タスクを最後まで終えられるか、を手で確かめる。
- 「ブランドガイドラインの色だから」は通常の文字のコントラストの例外にならない。

出典: https://www.w3.org/TR/WCAG22/ / https://www.w3.org/WAI/WCAG22/Understanding/

## ダークパターン（deceptive patterns）

ユーザーを欺く、操る、または十分な情報に基づく判断を妨げる設計。短期の数字は上がっても、信頼・継続率・法的リスクで返ってくる。
人気 EC 約 11,000 サイトの 10% 超、無料 Android アプリの 95% に見つかったという研究がある。軽いものはユーザーテストでも見落とされやすいので、**設計とレビューで名指しして潰す**。

| 類型 | 例 | 直し方 |
| --- | --- | --- |
| **解約困難**（旧称 roach motel） | 登録は数クリックなのに、解約は電話・引き留め画面を何枚も通らせる | 登録と同じ経路・同じ手間で解約できる |
| **隠れたサブスク** | 単発購入のつもりが継続課金。更新前の通知も無い | 継続課金であること・金額・周期・解約方法を購入ボタンの近くに |
| **confirmshaming** | 「いいえ、私は損をしたいです」 | 断る選択肢は中立な言葉で（「今はしない」） |
| **事前選択** | 追加オプションやメール配信の同意が最初からオン | 既定はオフ。必要なら明示的に選ばせる |
| **隠れコスト** | 最後の画面で手数料・送料が出てくる | 総額を早い段階で見せる |
| **偽の緊急性・希少性** | 実際には無いカウントダウン、「残り 1 点」 | 本当のデータだけを出す |
| **しつこい再要求（nagging）** | 断っても毎回出る通知許可やアプリ誘導 | 断ったら一定期間出さない |
| **見た目での誘導** | 断るボタンだけ灰色の小さな文字 | 選択肢を同じ重みで並べる |

- 本物のデータに基づく社会的証明（実際の購入数）や在庫表示は説得であって欺瞞ではない。好意的なレビューだけを見せて否定的なものを隠すのは欺瞞。
- 確かめ方: 「決断を急かしていないか」「断るときに恥ずかしさや罪悪感を覚えないか」を、最も弱い立場のユーザー（急いでいる人、高齢の人、母語でない人）の目で 1 手ずつ確かめる。

出典: https://www.deceptive.design/types / https://www.nngroup.com/articles/deceptive-patterns/

### 規制の動き（2026-11 時点。変わりやすい）

法的な判断が要る点は断定せず、「法務の確認が必要」と返答に書く。条文や施行状況を根拠にするなら、最新の一次情報を確かめてから書く。

- **EU デジタルサービス法（DSA）第 25 条**: オンラインプラットフォームに、利用者を欺く・操るインターフェースを禁じている。
- **EU Digital Fairness Act 案**（2026-11 公表、立法交渉中）: ダークパターンの禁止、オンラインの解約ボタン、依存を招く機能をオフにする権利などを含む。
- **米 FTC の Click-to-Cancel 規則**: 2024 年に確定したが、2025-07 に控訴裁が無効にした。FTC は 2026 年に規則づくりをやり直している。州の自動更新法は有効。
- **日本の特定商取引法 第 12 条の 6**: 通信販売の最終確認画面で、分量・価格・支払時期・解約条件などの表示を義務づけ、誤認させる表示を禁じている。

実務上の基準は「登録と同じ経路・同じ手間で解約できる」「総額と継続条件を、申し込む前に見せる」。

出典: https://dsa-library.com/article/25/ / https://www.ftc.gov/legal-library/browse/rules/negative-option-rule

## 信頼を作る

- **先に見せる**: 総額、手数料、送料、返品・解約の条件、連絡先を、支払い情報を求める前に見せる。
- **価値を見せる前に壁を置かない**: ログイン・会員登録・アプリのインストールを最初に要求しない。
- **小さなミスをなくす**: 誤字、リンク切れ、古い情報は信頼を大きく下げる。
- **外部とつながる**: 自社サイトの推薦文より第三者のレビューのほうが信頼される。
- **理由を言う**: 個人情報・権限・通知の許可を求めるときは、何に使うかをその場で書く。

出典: https://www.nngroup.com/articles/trustworthy-design/
